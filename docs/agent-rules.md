# 작업별 기준

이 문서는 프로젝트 고유 판단 기준이다. 조사·계획·리뷰·검증은 Superpowers, 코드 구현은 Ponytail을 사용한다. 다이어그램은 Stack Diagram을 사용한다.

# 프론트엔드 개발

## 개요

컴포넌트에서 훅과 API로 이어지는 저장소 흐름을 지키며 타입 안전한 모바일 우선 사용자 동작을 구현한다. 동작 변경과 버그 수정은 Ponytail 기준에 따라 필요한 테스트로 검증한다.

동작에 영향을 주지 않는 문서·표현·생성물 변경은 적합한 정적·시각·생성 검증을 수행한다. 단순히 파일 종류만으로 동작 변경을 제외하지 않는다. 금융·인증·API 동작과 사용자가 지정한 검증은 생략하지 않는다. 적용되는 스킬에 별도의 명시적 예외 승인이 있으면 AGENTS.md의 기존 승인 재사용 규칙을 따른다.

## 작업 절차

1. `AGENTS.md`, 기준 화면·기능 명세와 주변 구현·테스트를 읽는다. 필요한 자료만 조건부로 읽는다.
   - API·타입: `docs/api-layer.md`, `docs/api-spec.md`; 실제 코드와 생성 타입을 우선한다.
   - 인증·오류: `docs/auth.md`, `docs/error-handling.md`
   - 테스트·반응형: `docs/testing.md`, `docs/responsive-ui.md`
   - 제품·화면 계약: 존재할 때만 `../docs/specs/`, `../docs/design/`; 없으면 관련 코드·테스트를 확인하고 AGENTS.md의 명확화 규칙에 따라 진행한다. 남은 검증 공백은 보고한다.
   - 버전·명령: `package.json`과 lockfile을 진실 공급원으로 사용한다.
2. `git status`를 확인하고 관련 없는 사용자 변경을 보호한다. 요청한 동작으로 수정 범위를 제한한다.
3. 코드를 작성하기 전에 사용자에게 보이는 동작과 계약을 정의한다.
   - 필드명, 단위, 정밀도, null 허용 여부, 날짜 의미와 백엔드 오류를 확인한다.
   - 로딩, 빈 상태, 오류, 성공, 오래된 데이터와 미인증 상태를 정의한다.
   - 관련되는 경우 0, 음수, 누락 값과 금융 경계값을 포함한다.
4. 다음 데이터 흐름을 유지한다.

   `컴포넌트 -> src/hooks/use-*.ts -> src/api/<domain>.ts -> src/api/client.ts -> 백엔드`

   컴포넌트에서 API 모듈을 직접 호출하지 않는다. 서버 데이터는 TanStack Query에, 인증 식별 정보는 Zustand에 둔다.
5. 타입을 지키는 최소 변경을 구현한다. `any`, 하드코딩한 Query Key 문자열, 운영 코드의 `console.log`, 필요성이 증명되지 않은 절대 위치 지정을 사용하지 않는다.
6. 새 UI 기본 요소를 만들기 전에 기존 공통·Radix 컴포넌트와 디자인 토큰을 사용한다. 금융 의미를 색상에만 의존하지 않고 텍스트나 아이콘으로도 전달한다.
7. UI에 영향을 주는 변경은 모바일을 먼저 확인하고 데스크톱을 확인한다. 터치 영역, 넘침, 안전 여백, 키보드 접근, 포커스와 부호가 있는 값의 가독성을 점검한다.
8. 대상 테스트, 영향받은 테스트 묶음, 타입·빌드 검증과 변경 흐름에 필요한 Playwright 범위를 실행한다.

## 검증 단계

| 변경 범위 | 최소 명령 |
|---|---|
| 유틸리티·API·훅 | `npx vitest run <exact-test-file>` |
| 컴포넌트·화면 | `npx vitest run <exact-test-file>`와 `npm run build` |
| 핵심 사용자 흐름 | `npx playwright test <exact-spec>` |
| 저장소 전체 영향 또는 출시 검증 | `npm test`와 `npm run build` |

저장소의 정확한 경로를 사용하고 자리표시자 명령을 그대로 실행하지 않는다.

## 결과 형식

다음을 보고한다.

1. 구현한 사용자 동작과 영향받은 라우트·컴포넌트
2. API, 상태와 금융 정보 표시 결정
3. 변경에 선택한 검증과 근거
4. 모바일 증거를 포함한 검증 명령과 결과
5. 남은 위험 또는 제외 범위

## 흔한 실수

- “작은” API 호출이라는 이유로 훅 계층을 생략한다.
- 서버 응답을 Zustand에 저장한다.
- 0, 누락 값과 음수를 같은 대체값으로 표시한다.
- 데스크톱 정상 경로만 테스트한다.
- UI 변경과 관련 없는 포맷 변경을 같은 diff에 섞는다.

# 프론트엔드 UI 품질 검증

## 개요

하나의 정상 화면 캡처가 아니라 전체 사용자 동작을 검증한다. 모바일 웹, 상태 범위, 접근성과 정확한 금융 정보 표시는 출시 필수 조건이다.

## 검증 절차

1. `AGENTS.md`, 정확한 후보 빌드 또는 diff와 관련 구현·테스트를 읽는다. 반응형 기준은 `docs/responsive-ui.md`, 버전·명령은 `package.json`에서 확인한다. 존재할 때만 `../docs/design/`, `../docs/specs/`의 화면 계약을 읽고, 없으면 추측하지 않고 검증 공백으로 기록한다.
2. 테스트한 라우트, 계정 상태, 데이터 조건, 뷰포트, 브라우저와 빌드 식별자를 명시한다. 후보를 식별할 수 없으면 출시 판정을 내리지 않는다.
3. 변경과 평가 범위에 관련된 다음 상태 매트릭스를 확인한다. 비해당 항목은 사유와 함께 N/A로 기록하며 증거 부족을 N/A로 처리하지 않는다.
   - 로딩과 지연 응답
   - 빈 상태 또는 최초 사용 상태
   - 현실적인 최소·최대 콘텐츠의 성공 상태
   - 복구 가능한 API 오류와 복구 불가능한 API 오류
   - 미인증 또는 만료된 세션
   - 서버 데이터의 오래된 상태와 재조회 동작
4. 관련되는 경우 0, 양수, 음수, 누락 값, 긴 값, 소수점, 단위, 반올림, 통화, 기준일과 EOD 표현을 확인한다.
5. 360×800 같은 좁은 뷰포트에서 모바일을 먼저 확인한 뒤 일반 휴대전화 너비와 데스크톱을 확인한다. 넘침, 고정 내비게이션, 시트, 키보드 겹침, 안전 여백, 회전 영향을 받는 레이아웃과 터치 영역을 점검한다.
6. 키보드 순서, 보이는 포커스, 의미 있는 이름, 제목, 레이블, 대비, 모션 감소와 색상 이외의 정보 전달 등 상호작용과 접근성을 확인한다.
7. 컨트롤 클릭만이 아니라 최종 이동 결과까지 확인한다. 로딩·실패 안내에 원시 API 오류가 노출되지 않는지 확인한다.
8. 기존 Vitest와 Playwright 증거가 인수 조건을 직접 검증할 때 활용한다. 핵심 증거가 없으면 가장 좁고 안전한 테스트 명령으로 재현한다.
9. QA 단계는 AGENTS.md의 읽기 전용 범위를 따른다. 격리된 로컬 검증과 임시 산출물은 허용한다. 현재 또는 이전 대화에서 수정도 명시적으로 요청되었다면 검증 후 수정 단계로 전환하며 후속 요청을 다시 요구하지 않는다.

## 발견 사항 형식

발견 사항을 먼저 보고하며 각 항목에 다음을 포함한다.

1. 심각도: `차단`, `중요`, `경미`
2. 라우트·컴포넌트와 상태
3. 뷰포트와 재현 절차
4. 기대 결과와 실제 결과
5. 사용자 또는 금융 의사결정에 미치는 영향
6. 증거 위치

마지막에는 다음 중 하나로 판정한다.

- **통과** — 필수 상태와 모바일 흐름에 증거가 있고 차단 문제가 없다.
- **조건부 통과** — 승인된 비핵심 후속 작업만 담당자와 함께 남았다.
- **실패** — 필수 상태의 불일치가 재현되었다.
- **판정 보류** — 후보를 식별하지 못했거나 직접 검증을 시도한 후에도 필요한 모바일·금융·접근성·빌드 증거가 없다. 해당 조건은 미검증이며 출시를 승인하지 않는다.

## 최소 증거 매트릭스

| 영역 | 필수 증거 |
|---|---|
| 반응형 UI | 좁은 모바일과 데스크톱 결과 |
| 데이터 상태 | 로딩, 빈 상태, 오류, 성공 |
| 금융 값 | 0, 음수, 누락 값, 단위·날짜 의미 |
| 상호작용 | 진입 동작부터 최종 결과까지 |
| 접근성 | 키보드, 포커스, 이름·레이블, 색상 외 단서 |

## 흔한 실수

- 하나의 화면 캡처나 뷰포트만 보고 출시 가능으로 판단한다.
- “관찰되지 않음”을 결함이 없다는 증거로 기록한다.
- 사용자 정의 컨트롤의 키보드, 포커스 또는 스크린 리더 이름을 무시한다.
- API 오류를 사용자에게 적절한 문구로 간주한다.
- 금융 값의 기준일과 부호를 빠뜨린다.
