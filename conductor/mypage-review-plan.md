# 마이페이지(My Page) 코드 리뷰 계획

## 목적
- 마이페이지(더보기 탭)의 사용자 정보 관리, 앱 설정, 알림 설정 및 인증 흐름의 안정성과 UX 완성도를 분석합니다.
- 특히 소셜 로그인, 토큰 관리, 회원 탈퇴 등 보안 및 계정 관리 로직의 결함을 식별합니다.

## 핵심 분석 대상
1. **마이 탭 (`More.tsx`)**
   - 프로필 카드 데이터 노출 및 투자 성향 계산 로직 (`investorType`).
   - 닉네임 변경 모달의 유효성 검사 및 서버 연동.
   - 테마 설정(`next-themes`) 연동의 일관성.
   - 로그아웃 및 회원 탈퇴(AlertDialog) 흐름의 안전성.
2. **알림 설정 (`NotificationSettings.tsx`)**
   - 개별 알림 항목(야간 알림, 혜택 알림 등)의 토글 안정성.
   - 설정 변경 시 즉각적인 서버 반영 및 에러 핸들링.
3. **인증 흐름 (`Login.tsx`, `AuthCallbackHandler.tsx`)**
   - 소셜 로그인(OAuth) 콜백 처리의 견고함.
   - `auth-storage` 및 `localStorage` 토큰 이중 관리 로직의 정합성.
   - `AuthCallbackHandler`에서의 에러 케이스(인증 실패 등) 처리.
4. **비즈니스 로직 및 상태 관리**
   - `use-member.ts`: 프로필 업데이트, 알림 설정 변경, 탈퇴 훅.
   - `src/store/auth.ts`: `persist` 미들웨어 사용에 따른 하이드레이션 이슈 가능성.
   - `src/api/member.ts`, `auth.ts`: API 계약 준수 여부.

## 주요 체크리스트
- [ ] **보안**: 회원 탈퇴 시 `localStorage` 및 `auth-storage`가 완전히 클리어되는가?
- [ ] **성능**: `useMe` 훅의 호출 빈도가 적절한가? (불필요한 리렌더링 방지)
- [ ] **UX**: 닉네임 변경 시 즉시 UI에 반영되는가? (Zustand 상태 업데이트 확인)
- [ ] **예외 처리**: 소셜 로그인 도중 취소하거나 실패했을 때 사용자에게 적절한 피드백을 주는가?
- [ ] **일관성**: `MetricItem` 등 공통 컴포넌트의 스타일링이 디자인 시스템을 따르는가?
